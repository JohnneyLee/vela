# Vela 设计过程中的问题与解法

本文记录从划词翻译原型做到 **0.1.3** 试用包期间，反复踩过的坑、误判过的假设，以及最终怎么收口的。按主题归类，方便以后改同类问题时对照。

---

## 1. Cursor / Electron 取词失败

### 现象

在 Cursor 里选中中文（或其它文字），点动作条后提示「没有检测到选中的文字」。浏览器等普通应用正常。

### 曾误判的方向

- 以为只是「出条太早 / 太晚」或「点条后选区丢了」。
- 一度做成「松手立刻静默 Ctrl+C 缓存」或「先出条再异步复制」，在「能取词」和「出条变慢」之间反复横跳。

### 日志钉死的事实

在 `before_bar`、焦点仍在 `Cursor.exe` 时：

- `WM_COPY` / `Ctrl+C` 都显示发送成功；
- **剪贴板序号完全不变**（`seq_changed=false`）。

说明：不是时机 alone，而是 **注入复制没有让 Cursor 写出剪贴板**（Chromium / Monaco 对顶层 `PostMessage`、带 tag 的虚拟键注入常不吃）。

### 解法

1. **优先 UIA**：在焦点元素的**子树**里找带 `TextPattern` 的节点（Monaco 常在后代上，不只在焦点或父节点）。
2. 对 **`Chrome_RenderWidgetHostHWND`** 用 `SendMessageTimeout(WM_COPY)`，而不是只对顶层窗口乱 `PostMessage`。
3. 回退用 **无标签扫描码** `Ctrl+C` / `Ctrl+Insert`，并 `AttachThreadInput`。
4. 选区存活时尽量完成取词；点结果页时优先用缓存（若开启预取）。

### 相关启示

「发送成功 ≠ 应用接受」。诊断要记 **剪贴板序号、焦点进程、方法名**，不要只记「有没有选区」这种表面结果。

## 2. 「要快还是要稳」其实不是死结

### 矛盾表象

- 同步等复制再出条 → Cursor 曾能取词，但 picker 消息线程被堵，**其它应用出条也变慢**。
- 先出条再异步复制 → 出条快，Cursor 又取不中。

### 更准确的变量

复制发生在 **出条之前还是之后**，以及 **松手后等多久**，比「同步/异步」口号更重要。用日志 + 时机开关（`prefetch-debug.json`）可以把 H1（太早）/ H2（出条抢焦点）/ H3（按键没进）分开。

### 产品收口（当前默认）

- **默认关闭静默预取词**（隐私 + 删选区体验 + 少碰剪贴板）。
- 点小图标 → 打开结果卡 → **用户再点「译/释/润/读」才请求**，避免默认动作浪费 tokens。
- 需要实验时仍可用 `%APPDATA%\com.vela.desktop\prefetch-debug.json` 打开预取。

## 3. 静默预取词的副作用（隐私与终端）

### 风险

| 风险 | 说明 |
|------|------|
| 隐私 | 每次选中都复制，密钥可能进剪贴板历史 / 云剪贴板 / 其它监听程序；还原剪贴板也**撤不回**中间那一份。 |
| 整行复制 | VS Code 系空选区时 Ctrl+C 可能复制整行，缓存会脏。 |
| 终端 | 集成终端里无选区时 Ctrl+C 会**中断正在跑的程序**。 |

### 解法方向（已落地一部分）

- 预取词 **默认关**；终端 **不自动出入口**（仅热键）。
- 出入口期间：按键 / 右键 / 滚轮 / 点别处 → 立刻收起，事件放行。
- 长期最稳：Cursor / VS Code **伴侣扩展**（本机令牌、按需读选区，不碰剪贴板）——尚未做，见功能文档「可做」。

## 4. 动作条抢占与「选中是为了删除」

### 现象

用户选中文字常常是为了 Delete / 剪切，四个字的动作条又大又像「替你做决定」，感觉被打断。

### 解法（当前）

1. 选中后只出 **小入口图标**（品牌色圆标 + V），不直接摊开四按钮。
2. 点图标 → 进结果卡；**四功能在结果卡顶部点选后再执行**。
3. 图标默认够醒目；可编辑应用出条略延迟；终端不出自动入口。

曾试过「点图标展开四选一」：多一步、仍像中途打断，已去掉。

---

## 5. 润色能力不够用

### 现象

只有固定「力度」档位，选中大段文字无法按自定义要求改写。

### 解法

- 少量预设（只改错误 / 通顺自然 / 大幅重写 / 压缩变短）。
- **自定义要求**输入框；有自定义文案时优先写入 prompt。
- 结果卡上「按要求改写」/ Ctrl+Enter 重新生成。

---

## 6. 默认执行推荐动作浪费 tokens

### 现象

推荐高亮不一定是用户想要的；一点入口就跑翻译/AI，白耗额度。

### 解法

取词后进入 **等待选择** 状态：展示原文，提示点「译/释/润/读」再请求；点了才 `runAction`。

## 7. 截图 / 钉图 / 权限类问题（早期）

| 问题 | 解法要点 |
|------|----------|
| 截图 overlay 空白、Esc 关不掉 | 就绪事件 + 全局 Esc；检查窗口/ACL。 |
| PNG alpha=0 看不见 | 强制不透明通道。 |
| Tauri 2 命令被拒 | capabilities / permissions 补全 overlay、screenshot、bar 等。 |
| 钉图难拖、难关 | 工具条 + `startDragging`，明确关闭入口。 |
| OCR 结果挡原文 | 卡片放到右侧/下方，不盖住选区文字。 |

---

## 8. 剪贴板备份与占用

### 现象

部分应用剪贴板带 GDI 预览等不可字节拷贝的格式，整次取词被判死；或剪贴板被占用。

### 解法要点

- 跳过无法完整备份的预览格式；关键格式失败才算不可还原。
- 占用退避重试；可选「允许部分备份」开关。
- 日志记占用者进程名，**不记文字内容**。

## 9. 安装与部署混淆

### 现象

开发时 `build:fast` 拷到 `%LOCALAPPDATA%\Vela\vela.exe`，与正式安装包路径相同，容易以为「还有另一份旧目录」。

### 事实

NSIS 安装目录就是 `%LOCALAPPDATA%\Vela\`；开发覆盖与安装包覆盖的是**同一份** `vela.exe`。快捷方式也指向这里。发试用包用 `npm run tauri build` 生成 `Vela_x.y.z_x64-setup.exe` 即可。

---

## 10. 方法小结（可复用原则）

1. **先日志再盲调时序**；日志禁止带选区正文。
2. Electron 取词：UIA 子树 → 渲染窗 `WM_COPY` → 扫描码复制；别假设 SendInput 一定有效。
3. **预取词默认关**；终端慎用 Ctrl+C。
4. 入口要轻；**费钱的 AI 调用必须用户点名动作后再跑**。
5. 产品假设「有选区 ≈ 要翻译」过强时，用延迟、仅热键、小图标、按键即消来降打扰。

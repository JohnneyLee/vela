# Vela 手动更新设计

## 目标

让已安装的 Vela 用户可以在设置页主动检查新版本，并在查看版本和更新说明后选择是否安装。应用不在后台自动下载或安装更新。

## 用户流程

1. 用户在「设置 → 通用」点击「检查更新」。
2. 应用查询 GitHub Releases 的稳定版更新清单，显示检查中、已是最新版本或可用更新及版本说明。
3. 用户明确确认后，应用下载更新包、校验 Tauri updater 签名并安装，然后按插件要求退出或重启。
4. 检查失败、签名不匹配、下载失败或用户取消时，显示可理解的状态；当前安装继续可用。

## 更新来源与完整性

- 使用现有 GitHub 仓库的 Releases 作为唯一稳定更新源，不引入自建服务器。
- 每个 Windows x64 发布包含 NSIS 安装包、Tauri updater 归档及签名，以及符合 Tauri 静态更新清单格式的 `latest.json`。
- 应用内固定 updater 公钥；发布私钥只放在受保护的发布环境或本地安全存储中，禁止提交到仓库、安装包或日志。
- Tauri updater 签名验证失败时必须拒绝安装；不允许不安全 HTTP、跳过签名或静默降级。
- 更新检查仅在用户点击时发生。请求会向 GitHub 暴露常规连接元数据（如 IP、请求时间和资源路径）；不附带原文、译文、API Key 或用户标识。

## 组件范围

- Rust：注册 Tauri updater 插件，构建检查、下载、安装和错误处理命令；仅允许设置窗口调用所需命令。
- Tauri 配置：添加 updater 公钥、HTTPS 更新清单地址和 Windows 更新产物配置。
- 设置页：通用区域增加手动检查按钮、状态/版本说明展示，以及安装前确认。
- 发布流程：版本号在 `package.json` 与 `src-tauri/tauri.conf.json` 保持一致；构建签名产物并随 Release 上传清单。

## 验收

- 无更新时显示当前版本已是最新；有更新时显示版本号与说明，并等待用户确认后才下载。
- 用户取消后不安装；更新包签名错误时安装必定失败并给出提示。
- 下载/安装成功后版本更新，用户设置、API Key 和离线模型仍保留。
- 离线或 GitHub 不可达时不影响翻译功能，状态提示可以重试。
- 自动更新检查默认不存在；检查请求不发送翻译文本或密钥。

## 发布前置条件

首次启用前必须生成 updater 密钥对，将公钥配置到应用，并将私钥与密码分别保存为 GitHub Actions 仓库 Secrets（`TAURI_SIGNING_PRIVATE_KEY`、`TAURI_SIGNING_PRIVATE_KEY_PASSWORD`）后验证签名 Release 流程。私钥不能提交到代码仓库或普通构建产物。安装包当前未代码签名；updater 签名只验证更新包来源与完整性，不会消除 Windows SmartScreen 的未知发布者提示。开发机的私钥已保存在 `%USERPROFILE%\.tauri\vela-updater.key`，密码文件由当前 Windows 账户 DPAPI 保护。仓库管理员可在本机完成 `gh auth login` 后运行 `scripts/configure-updater-secrets.ps1`，脚本会把两个值通过标准输入写入 GitHub Secrets，不输出密钥或密码。

## 不在本次范围

- 后台定期检查、自动下载或无确认安装。
- 灰度发布、回滚服务、强制升级、分析或更新遥测。
- 替换 NSIS 安装器、代码签名证书或跨平台更新支持。
